ML-DSA: byte-exact NIST ACVP conformance for key generation

Rebuilt ML-DSA against FIPS 204 and the reference implementation. Key
generation now reproduces all 75 NIST ACVP keyGen vectors byte-for-byte,
which pins the NTT, RejNTTPoly, RejBoundedPoly, Power2Round, Decompose and
every encoding and key-field layout.

Fixes:

- NTT replaced with the FIPS 204 Alg. 41/42 transform plus the Montgomery
  reduction. The previous generic negacyclic transform was mathematically
  correct but used a different output ordering, which broke byte-level
  conformance.
- RejNTTPoly now decodes the 23-bit candidate from three bytes, using the
  SHAKE128 single-stream squeeze and (col, row) seeding order.
- RejBoundedPoly replaces centre-binomial sampling: nibble-based rejection
  with bound 15 for eta=2 plus the 205*t>>10 fold, bound 9 for eta=4, over a
  64-byte seed with a 2-byte nonce.
- Decompose and UseHint fold the top quotient and return a signed low part,
  matching the reference exactly (0/3000 mismatches over random inputs).
- Power2Round operates on the standard representative; t0 is stored as
  2^(d-1) - t0 and t1 as a raw 10-bit limb.
- The public matrix A is k x ell, not k x k.
- The 2^d shift on t1 is applied in the coefficient domain before the NTT.
- w = A y now transforms y before the pointwise product.
- Hints are built from LowBits(w) - c*s2 + c*t0, matching the streamlined
  FIPS 204 formulation.
- Signature hints use the omega index bytes plus k cumulative counters,
  validated on unpack for strong unforgeability.
- SampleInBall follows Alg. 29 with a tau-parameterised rejection loop.
- FIPS 204 context strings are supported end to end.
- bitunpack applies (limb - alpha) mod 2^w, per the specification.
- Parameter tables corrected: gamma2 = (q-1)/88 for ML-DSA-44, omega
  80/55/75, and sk_len now derives to the published 2560/4032/4896.

Adds the package surface, CLI, tests and documentation:

- quantumpost/__init__.py, __main__.py, cli.py: public API plus a CLI with
  keygen, encaps, decaps, sign, verify, list, info, bench and self-test.
- quantumpost/combine.py: an X-Wing style hybrid KEM combiner, and composite
  signing that binds a classical public key into the ML-DSA signature.
- tests/: 84 tests covering hash KATs, the NTT against a schoolbook oracle,
  packing round trips, published sizes and parameters, implicit rejection,
  signature round trips and negative tests, the combiner, RNG hooks and CLI.
- tools/check_acvp.py: reproduces the conformance report against NIST vectors.
- README, docs/{ARCHITECTURE,CONFORMANCE,DEPLOYMENT,THREATS}.md, SECURITY.md,
  CONTRIBUTING.md, LICENSE, pyproject.toml, Makefile and CI.

Known gap, documented in docs/CONFORMANCE.md and reported by the checker:
ML-DSA signatures verify internally and correctly reject all 36 ACVP negative
cases, but 9 ACVP positive cases do not yet verify, so signatures are not
yet interoperable with NIST's implementation. ML-DSA key generation and
ML-KEM are unaffected.
